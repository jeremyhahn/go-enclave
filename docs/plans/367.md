# Plan: a runnable example of the conformance suite (#367)

## Objective

`backendtest.TestBackend(ctx, cfg)` is the backend author's entry point, but
the package has no `Example` function. Add `ExampleTestBackend` in package
`backendtest_test`: it runs the suite against the shipped locked-memory
backend (`enclave.DefaultBackend()`) with a minimal valid `Config`, prints
one stable line on success, and carries an `// Output:` comment so
`go test` runs it. Link it from `docs/backend-conformance/user.md`.

## Slices, in order

1. Example (test commit): `backendtest/example_test.go` with
   `ExampleTestBackend`. The locked-memory backend is no Importer, so its one
   handle case makes handles with `New` (`enclave.NewMemorySized`), claiming
   what a locked region claims. The backend claims `CapabilityProbe` only.
   Test: `go test ./backendtest/` runs the example against its Output line.
2. Fixes: one commit per defect the example exposes, if any. Found: the
   residue sweep failed a case whose material is one repeated byte (a zeroed
   region); it now reports it unmeasured (test
   `TestBackendConformance_UniformMaterialUnmeasured`). And the feature-map
   build gate took `docs/plans/` for a feature; it is exempt like
   `docs/reference/`.
3. Docs and changelog: a paragraph in `docs/backend-conformance/user.md`
   pointing at the example; `changelog.d/367-backendtest-example.md`
   (`### Added`).
4. Simplify pass over the new test code, no behaviour change.

## Out of scope

- New checks in the suite or changes to `Config`.
- Examples for other backends (secret memory, hardware backends).
