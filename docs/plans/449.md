# Plan: SPEC row locked-memory-budget (#449)

## Objective

Close row `locked-memory-budget` of [docs/SPEC.md](../SPEC.md):
`Allocator` admits against a budget in page-rounded locked bytes before
allocating, by compare-and-swap; refunds failed constructions; discovers
`RLIMIT_MEMLOCK`; retunes at runtime; one process allocator installed by the
binary and drawn on by libraries.

The row is already marked shipped in SPEC.md. What remains are the folded
items: tests that prove the budget stays exact under concurrent retuning, and
that the page rounding of `lockedSize` holds at its boundaries.

## Slices, in order

1. This plan.
2. Fold PR #391 (`git merge --no-ff`): `allocator_retune_race_test.go` races
   admissions and destroys against `SetLimit`, `ForceLimit` and `TransferTo`
   and checks the budget's in-use count returns exact (#377).
3. Fold PR #413 (`git merge --no-ff`): `mapping_test.go` gains a boundary
   table for `lockedSize` and a big-integer fuzz target that checks it
   against `math/big` arithmetic.
4. Run `make test-enclave` and `make test-locked-memory-budget`; fix what
   fails on the merged tree.
5. Merge main; the retune race test required a refusal its setup did not
   force. After the race it now forces one on each side (limit lowered to
   one page, filled, a second admission refused, limit restored).

## Tests each slice adds

- Slice 2: the retune race tests, run under `-race` at `-cpu=1,2,8`.
- Slice 5: `forceRetuneRaceRefusal`, a deterministic refusal per side.
- Slice 3: the `lockedSize` boundary table and `FuzzLockedSize` (its seed
  corpus runs as a unit test).
