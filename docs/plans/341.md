# Plan: a runnable example of the conformance suite (#341)

## Objective

`providertest` has no `Example`, and no test compiles the `Config` snippet in
`docs/provider-conformance/user.md` (`New`, `Modes`, `Logf`). Add runnable
examples that use the same field names as the guide, so `go doc` shows a
working call and `go test` keeps it compiling and passing.

## Slices

1. `providertest/example_test.go` (package `providertest_test`):
   - `ExampleTestProvider` runs the suite against
     `enclave.NewSoftwareProvider()` in both modes it serves and prints a
     one-line verdict checked by `// Output:`. `Logf` discards the notes,
     because anything it wrote to stdout would break the output check.
   - `ExampleTestProvider_invalidConfig` passes an empty `Config` and shows
     that the error matches `providertest.ErrInvalidConfig`.
   Tests: both examples run under `go test -race ./providertest/` and
   `make test-fips`.
2. `changelog.d/341-providertest-example.md`: an `### Added` entry.

## Out of scope

- Edits to the provider guide (other work owns the provider docs).
- Production code changes in `providertest`.
