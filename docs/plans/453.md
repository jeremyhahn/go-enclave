# Plan: SPEC row backend-conformance (#453)

## Objective

`backendtest.TestBackend(ctx, cfg)` holds a backend to the seam: handle
lifecycle, exact capability claims in both directions, import wiping, nonce
binding through the author's `VerifyEvidence`; it fails closed. This row
folds the three open per-item PRs into one branch and one PR.

## Slices, in order

1. Fold PR #359 (#330): a shared refusal check for backends whose hardware is
   absent (`backendtest/refusal.go`). Tests: `backendtest/refusal_test.go`
   (typed nil, leak, unbounded or unmeasured budget, ended context, Probe
   panic) and the allocator read in `allocator_test.go`.
2. Fold PR #380 (#367): `ExampleTestBackend`, a runnable example of the
   suite on the locked-memory backend, and the uniform-material residue fix
   it exposed. Tests: `backendtest/example_test.go`,
   `backendtest/backendtest_test.go`.
3. Fold PR #427 (#376): one contract table for every exported error type of
   `backendtest`, and the `FindingsError` message fix. Test:
   `backendtest/errors_contract_test.go`, which must also cover the error
   types slice 1 adds.
4. Changelog: one `changelog.d/backend-conformance.md` fragment carries all
   three; no per-issue fragment file remains.
5. docs/SPEC.md: the row stays `shipped`; the PR closes #453.

Each fold is a `git merge --no-ff` of the PR head; conflicts keep both sides'
intent. Gates per slice: `make test-backendtest`, `make test-enclave` (slice
1 touches `allocator.go`), `make test-backend-conformance`.

## Out of scope

- New backends, hardware device paths, the TPM and arm-trustzone modules.
- Integration tests needing Docker (CI runs them).
