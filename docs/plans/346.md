# Plan: TPM command-response fuzz and malformed-response tests (#346)

## Objective

The TPM backend (`backends/tpm`) parses the device's answer to every
authorized command in `execute` (`unseal.go`), splits TPM2B fields with
`cut2B`, and pages handle lists in `listType` (`recover.go`). Each of these
reads untrusted bytes. This row adds table tests for malformed responses
and fuzz targets for the parsers, and fixes any defect they expose.

## Slices

1. Tests (`backends/tpm/response_test.go`, no build tag):
   - `execute` table over a scripted stream transport and a fake session:
     short header, header without a parameter size, parameter size past
     the end, wrong tag, non-success code with and without a body,
     truncated and trailing authorization area, a session whose
     `Validate` fails. Each returns a typed error, never panics, and the
     command buffer is wiped before it is freed.
   - a test that `send` refuses a response shorter than the header, so
     `execute` may read the response code before checking the length.
   - `listType` table: MoreData without progress, foreign handle types,
     more handles than asked, handles below the requested start, the
     `maxListedHandles` bound across pages, a non-handle capability.
   - `FuzzExecuteResponse` and `FuzzCut2B` with seed corpora under
     `testdata/fuzz/`.
   - A case that exposes a defect is committed skipped with its reason.
2. One fix commit per defect, removing its skip.
3. Run each fuzz target 60 s; add new interesting inputs to the corpus;
   changelog fragment `changelog.d/346-tpm-response-fuzz.md`.

## Out of scope

- The sealed-blob parser (`blob.go`, `blob_test.go`): separate work.
- Hardware or swtpm runs: the conformance suite already covers them.
