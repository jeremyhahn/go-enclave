# Plan: SPEC row arm-trustzone (#458)

## Objective

Ship SPEC row `arm-trustzone`: the OP-TEE backend in the nested module
`backends/armtrustzone`, pure Go over `/dev/tee0`, that probes the trusted
application, fills memory enclave handles from its random-number command at
rank 2 and passes `backendtest` on the OP-TEE fixture
(`make integration-test-arm-trustzone`). The backend itself is on main; this
row closes the test gaps the folded items name and marks the row shipped in
`docs/SPEC.md`.

## Slices, in order

1. Fold the open per-item PRs into the row branch, each with
   `git merge --no-ff <head>`, keeping both sides' tests:
   - #373 (#337): `FuzzUnprotect`, a fuzz target for `KeyProtector.Unprotect`
     over the fake TEE.
   - #393, #426 (#375): one contract table holding every exported error type
     to the error contract (`errors.Is` on the sentinel, `Is`, `Unwrap`).
     The two tables overlap; #426's `TestErrorContract`, with its
     completeness check, is the one table. #393's duplicate goes, and its
     one exact message no row checks (a `DeviceError` with no cause) moves
     to `TestDeviceErrorUnwrap`.
   - #394: `Connect`, `Connector`, `Probe` and `Close` edges.
   - #395: `FuzzParseUUID` against an independent oracle, a `hexDigit` table,
     and the `parseUUID` fix the fuzz target found (digit pairs at fixed
     offsets) with its corpus entry.
   - #422 (#347): `Backend.Random` sizes and failures and `Backend.Close`
     over the fake TEE.
   - #429: the kernel driver, `ioctlRet` and `openClient` on non-TEE fds.
   Tests: each PR's own tests; `make test-backends` passes after every merge.
2. Changelog: the folded PRs' `changelog.d/arm-trustzone.md` names no
   `docs/<feature>/` folder, so its entries move into
   `changelog.d/backends.md`, the fragment of the feature the backend
   belongs to, beside the `### Fixed` entry for the `parseUUID` fix.
3. The row already reads `shipped` in `docs/SPEC.md`; the row's PR closes
   #458 and leaves the table as it is.
4. Fold-up fixes: one `openFDs` helper (two PRs each declared one) and no
   skip guard in the kernel test.

## Out of scope

- New backend behaviour beyond the `parseUUID` fix.
- The OP-TEE fixture image and its CI job (shipped with #206).
- Hardware runs on a real TrustZone board.
