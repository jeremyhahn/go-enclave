# Plan: runnable examples for the public API (#333)

## Objective

pkg.go.dev is the API reference of the module (docs/SPEC.md Interfaces,
docs/README.md), but the root package has no `Example` functions and the
user-guide snippets are compiled by nothing. Add testable examples in package
`enclave_test` and make the user-guide snippets agree with them.

## Slices, in order

1. Examples with their expected `// Output:` blocks, written from the user
   guides (`example_test.go`, package `enclave_test`):
   - memory enclave: `NewMemory`, `NewMemoryCopy`, `NewMemorySized` with
     `WithBytes` and `Freeze`, `Destroy`;
   - locked-memory budget: `NewAllocator` (a standalone budget, its
     `Limit`, `InUse` and `Available`), `SetAllocator` (compiled only: the
     process allocator is one-shot per process, so a run in the test binary
     would depend on test order);
   - backend detection: `Detect`, printing only what holds on any host;
   - shutdown sweep: `WipeAll` under a deadline.
   Test: `go test -run Example ./`, which fails where a guide is stale.
2. Fix: correct the examples or the guide snippets until every example passes
   and each snippet in docs/memory-enclave, docs/locked-memory-budget,
   docs/backend-detection and docs/shutdown-sweep user.md matches its example
   or links it on pkg.go.dev.
3. Changelog fragment `changelog.d/333-examples.md`.

## Acceptance

`go test -run Example ./` passes and is deterministic (three runs, and with
`-race`); `make test`, `make lint` and `make check-changelog-assembly` pass.
The examples use only exported API.

## Out of scope

- Sealing examples and the sealing guides (another change owns them).
- `HardenProcess` and `CoreDumpsDisabled`: they change process-wide state, so
  they stay guide snippets only.
- Any production code change.
