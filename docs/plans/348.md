# Plan: the residue check against each way a provider can keep a key (#348)

## Objective

`providertest`'s residue check (`checkNoResidueAfterUnprotect` in
`providertest/residue.go`) is the suite's promise that a provider retains
nothing of the key after `Unprotect`. The existing Linux tests plant a key two
ways (a heap copy; a file or device mapping). This epic holds the check to each
retention strategy a provider could use, and fixes the check where one slips
past it.

## Slices, in order

1. Test: `providertest/residue_matrix_linux_test.go` (`//go:build linux`), a
   table of deliberately leaky providers run through `TestProvider`:
   - a package-level slice; a map value; a `sync.Pool`; a buffered channel;
   - a parked goroutine holding the key on its stack;
   - a kept `string` conversion;
   - an anonymous private `mmap`; an anonymous shared `mmap`;
   - an undestroyed second memory enclave;
   - only the first half of the key; only the last half;
   - the clean provider, which must pass.
   Each leaky case asserts a `*FindingsError` whose only finding is a
   `*PropertyError` on the residue property (or a documented
   `*NotMeasuredError`). Cases the check misses today are skipped with
   `t.Skip("miss: ...")`.
2. Fix: for each miss, a commit in `residue.go` removing its Skip; or, if the
   miss cannot be measured, one paragraph in
   `docs/provider-conformance/engineering.md` and the case changed to assert
   the documented outcome.
3. Changelog fragment `changelog.d/348-residue-matrix.md`.

## Tests

`go test ./providertest/`, `make coverage-providertest`, `make lint`;
`GOOS=darwin go vet ./providertest/` builds (the table is Linux-only).

## Out of scope

- `example_*_test.go` files in `providertest` (separate work in flight).
- SPEC.md; residue checks on non-Linux platforms; partial copies shorter than
  half the key.
