# Plan: the standing maintenance row

## Objective

The maintenance row takes every open dependency and CI branch into main with
its history, so no commit is lost. Each branch arrives as a `--no-ff` merge;
nothing is rebased, squashed or cherry-picked.

## Slices

1. SPEC and ROADMAP carry the maintenance row. (Merged.)
2. Merge the open CI branch for hosted runners:
   - `.github/workflows/ci.yml` and `.github/workflows/code-review.yml` are
     fleet templates: main's versions are kept exactly.
   - A repo-side change stays only where it passes against main's ci.yml.
     A buildgates test or fixture that only checked the branch's ci.yml
     edits is removed in its own commit after the merge.
   - Tests: `build/ci/buildgates` `go test ./...`, `make lint`,
     `make lint-gates` on the merged tree.
3. Merge the devcontainer guard test branch:
   - The merge keeps main's layout: the helper lives in
     `test/internal/devcontainer/`, and the branch's feature-map skip for
     `test/integration/internal` is dropped, since that path is gone.
   - A separate commit carries the guard cases main lacks (the 64-bit
     overflow bounds of the env parsers) into `devcontainer_test.go`; the
     rest duplicate main's cases or needed a skip.
   - Tests: `make lint-integration` (runs the package), `make lint-gates`.

## Out of scope

- Changes to the fleet templates themselves.
- New gates or tests beyond what the merged branches bring.
