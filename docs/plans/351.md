# Plan: make fuzz (#351)

## Objective

The root package and the backend modules carry native Go fuzz targets, but no
Makefile target fuzzes them: `go test` only replays their seed corpora. Add
`make fuzz`, backed by `build/fuzz/fuzz.sh` (POSIX sh), which finds every
`Fuzz` function in the root module and in each `BACKEND_MODULES` module and
fuzzes each for a bounded time.

## Behaviour

- Discovery: `go test -list '^Fuzz' <pkg>` for each package of the root module
  and of each backend module.
- Run: `go test -run '^$' -fuzz '^Name$' -fuzztime "$FUZZTIME" <pkg>` per
  target, from the target's module; `FUZZTIME` defaults to 30s.
- Selectors: `FUZZ` (an extended regexp on target names) and `FUZZ_PKG` (an
  extended regexp on import paths).
- A one-line summary per target (`ok` or `FAIL`, module, package, target).
- First failure stops the run: it prints the package, the target and the
  failing input path under `testdata/fuzz/`, and exits non-zero.
- Nothing found (after the selectors) is refused with a non-zero exit.

## Slices, in order

1. Test commit: `build/fuzz/fuzz_test.sh` with a stub `go` on `PATH` and a
   `check-fuzz-runner` target. Cases: discovery across the root and two
   backend modules, `FUZZ`, `FUZZ_PKG`, the failure path (package, target,
   input path, non-zero exit, later targets not run), the empty case, a bad
   `FUZZTIME`. It fails because `fuzz.sh` does not exist yet.
2. Code commit: `build/fuzz/fuzz.sh`, the `fuzz` target, `build/fuzz/*.sh`
   in `lint-scripts` under `--shell=sh`, `check-fuzz-runner` in `lint-gates`.
   The test passes.
3. Run `make fuzz FUZZTIME=5s` once; docs section in
   `docs/build-and-release.md`; changelog fragment.

## Out of scope

- Any CI workflow change (no scheduled fuzz job).
- New fuzz targets, corpus changes, SPEC.md and ROADMAP.md.
