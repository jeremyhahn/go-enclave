# Plan: the backend registry under concurrent use (#369)

## Objective

Prove the named backend registry in `backend.go` (`Register`, `Lookup`,
`BackendNames`, guarded by `backendsMu`) correct when many goroutines use it
at once, and fix any defect the proof exposes.

## Slices, in order

1. Test: `backend_registry_race_test.go`, `TestRegistryConcurrent`, run under
   `go test -race -count=5 -run TestRegistryConcurrent .`. Subtests:
   - `RegisterOnce`: N goroutines register distinct names while M goroutines
     re-register the same names; each name registers exactly once and every
     other attempt fails with `*BackendExistsError` naming it.
   - `NamesSnapshots`: readers call `BackendNames` throughout; every snapshot
     is sorted, duplicate-free, holds the locked-memory name, and is a
     superset of the reader's previous snapshot.
   - `LookupAfterRegister`: once `Register` returns nil, `Lookup` of that
     name never fails and returns the registered backend.
   Every name the test adds is removed with `t.Cleanup`, as
   `registerForTest` does.
2. One fix commit per defect the test exposes, each dropping its
   `t.Skip("defect: ...")`. None expected: `Register` checks and inserts
   under the write lock, readers copy under the read lock.
3. Changelog fragment `changelog.d/369-registry-race.md`, then a simplify
   pass over the new test (no behavior change).

## Out of scope

- Unregistering backends (the registry has no public removal).
- Detection and `Sweeper` paths that also take `backendsMu`.
- Any change to `backend.go` that no failing test asks for.
