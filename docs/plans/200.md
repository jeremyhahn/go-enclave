# Plan: nvidia-blackwell backend (#200)

Design: [docs/backends/nvidia-blackwell.md](../backends/nvidia-blackwell.md).
Where its open questions leave a choice, the plan takes the recommended
option: a composing backend (Q1) given its CPU TEE backend as a constructor
argument (Q2), rank `inner.Rank() + 1` (Q3), CMW evidence with the GPU nonce
`SHA-256(nonce)` (Q4), go-nvml (Q5), Blackwell only with single-GPU first (Q6),
the conformance harness in `test/integration` (Q7).

## Objective

A nested module `backends/nvblackwell` (its own go.mod, requiring a released
go-enclave and golang.org/x/sys, never required by the root; nothing
registers at import) that composes a CPU TEE backend with the GPUs' evidence
and readiness gate, and refuses with typed errors on every host without the
hardware.

## Slices

1. **Module, typed errors, probe, refusal path** (done): `errors.go` (the
   "Failure modes" errors, `PlatformError`, `DriverError`); `Probe(ctx)`
   reads `/proc/driver/nvidia/version` on linux, `PlatformError` elsewhere;
   `New(inner)` refuses an inner that is not Importer, Attester, Prober and a
   confining Confiner, then runs Probe. Tests: errors, the version parser on
   fixed buffers, Probe without the driver, New's refusals.
2. **Import** (done; landed before the NVML probe): delegates to `inner`
   and wraps the handle (ByteAccess and Freezer, `As` reaches inner's); a
   handle without both is destroyed and refused. Tests over a test inner on
   `enclave.NewMemory`.
3. **NVML probe** (done): go-nvml v0.13.4-1, loaded after the driver check.
   `gatherNVML` (linux and cgo) only reads the device count, architectures,
   CC state and settings and ready state into an `nvmlSnapshot`;
   `checkSnapshot` (every GOOS, no device) refuses each forbidden state with
   its typed error. Without cgo: `NVMLError`. Tests: `checkSnapshot` on fixed
   snapshots, one per refused state.
4. **Attest** (this slice): `Attest(ctx, nonce)` checks ctx and the nonce
   (1 to 64 bytes, else `enclave.ErrInvalidNonce`), runs Probe and returns
   its typed refusal unchanged, asks inner for the CPU evidence over the
   nonce as given, then each GPU (`Device.GetConfComputeGpuAttestationReport`
   over `SHA-256(nonce)`, `Device.GetConfComputeGpuCertificate`). `Data` is
   a CMW JSON collection: `cpu` and one nested collection per GPU (`gpu0`,
   ...) holding its report, CEC report when present, and both PEM chains.
   - Tests: the encoder on fixed inputs (records, nesting, base64url, the
     refusals); the nonce derivation; Attest on a host without the driver
     returns Probe's error and never reaches inner; the nonce bounds.
   - Open: the CMW text is not yet copied into `docs/reference/` (the lane
     could not fetch it); the member media types other than
     `application/pem-certificate-chain` have no registration.
5. **Conformance**: backendtest on the real part, from `test/integration`
   behind its own build tag (Q7).

## Out of scope

No simulator, emulator or mock device. No Hopper, no NVSwitch evidence, no
setting the ready state (the platform's attestation agent does that). No
code for any GOOS but linux beyond the refusing stub.
