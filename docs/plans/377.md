# Plan: issue 377, allocator retune race test

## Objective

Prove that an Allocator's budget accounting holds when admissions and
destroys run concurrently with `SetLimit`, `ForceLimit` and `TransferTo`:
no allocator is overcommitted at any observed point outside a forced
lowering, refusals are typed `*BudgetError`s, every byte admitted is released
by the end of the run, and transfers conserve the sum of the two limits.
