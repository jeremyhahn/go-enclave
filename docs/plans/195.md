# Plan: the i.MX 95 secure-enclave row leaves go-enclave

## Objective

The i.MX 95's secure enclave holds keys only and gives applications no
protected memory, so it fails the [SPEC scope](../SPEC.md#scope) test (the same
test as the Mac Secure Enclave). It moves to go-xkms, which
imports the history of the moved files from go-enclave's main. On the i.MX 95,
TrustZone/OP-TEE (`backends/armtrustzone`) stays go-enclave's backend, but
today it holds bytes in normal-world memory, readable by the process and
kernel; secure-world storage (the vault trusted application) is planned. This
change only removes the files here.

## Slices

1. One docs-and-build commit:
   - `docs/SPEC.md` Scope: a note that the enclave holds keys only and moved to
     go-xkms, and that `backends/armtrustzone` stays the i.MX 95 backend,
     holding bytes in normal-world memory today, with secure-world storage
     (the vault trusted application) planned.
   - `pm/rows.md`: drop the row from the no-open-work list.
   - Delete the row's proposal page under `docs/backends/` and its index rows
     in `docs/README.md` and `docs/backends/user.md`.
   - Delete the row's nested module under `backends/` and drop it from
     `BACKEND_MODULES` in the `Makefile`.
   - `changelog.d/backends.md`: replace the module's entry with a removal
     entry naming go-xkms; `docs/README.md` Upgrading gets a short note.
   - Tests: none added; the removed module's tests leave with it.
     `make test-backends` runs the remaining backend modules.

## Out of scope

- The go-xkms import of the moved files.
- Any change to `backends/armtrustzone`.
