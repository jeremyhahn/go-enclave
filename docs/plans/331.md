# Plan: tie the memscan signal count to the needle comparison (#331)

## Objective

The signal-frame test in `internal/memscan/plant_linux_test.go` counts a
signal only when it lands inside a marked compare window. Today a window
runs from the end of a buffer fill to the return of `mappingContains`, so it
also covers the buffer clear `mappingContains` runs as it returns. A counted
signal may have landed in that clear rather than in the needle comparison.
Narrow the window so it never covers the clear, with no production change.

## Approach (test only)

Each search of a pass reads a region of many buffers, not one. The test's
reader opens a window only on a read after which `mappingContains` stays in
its loop: a full read with no error that ends before the region does, over
memory that cannot hold the needle. The next read closes it as it starts.
So every window spans one `contains` call over the filled buffer and the
loop's offset arithmetic, and ends before the next fill; the final read,
after which the search returns and clears its buffer, opens no window.

## Slices

1. Test commit: a negative control, `childClear`, whose reader reads
   nothing, so each search skips its compare and only clears a 64 MiB
   buffer. On the current counter its signals count and the control fails.
2. Fix: the reader opens a window only on a read that keeps the search in
   its loop; each pass's search reads 16 buffers. The comments on
   `readParent` and `markedReader` state the narrowed claim. The control
   passes; the main test still reaches its minimum.
3. Mutation check: open a window on every read again; the control fails.
   Restored.
4. Changelog: `changelog.d/328-memscan-signal-test.md` matches the test as
   it runs; `changelog.d/331-memscan-signal-count.md` is new.

## Tests

`go test -race -count=1 -cpu=1,2,8 ./internal/memscan/` three times;
`make lint`; `make coverage-profile-memscan`. The needle stays 32 bytes
with a nonzero first byte.

## Out of scope

Any change to `internal/memscan` production code. Proving the signal hit
the byte-compare instructions rather than the loop's offset arithmetic
between two reads: that arithmetic never touches the needle.
