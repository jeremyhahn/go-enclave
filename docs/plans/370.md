# Plan: tests for release-tag.sh's tag refusal (#370)

## Objective

`build/ci/release-tag.sh` turns `GITHUB_REF` into `tag=` and `sha=` lines in
`$GITHUB_OUTPUT` and refuses a tag that is not a plain version string. No
buildgates test covers it. Add one that runs the script with `sh`, as
release.yml does, against a scratch git repository holding the tag.

## Slices

1. Test: `build/ci/buildgates/release_tag_test.go`.
   - `v1.2.3` and a pre-release tag pass and write exactly `tag=<name>` and
     `sha=<HEAD of the scratch repository>`.
   - A branch ref, an empty ref, an unset ref, and tags holding shell
     metacharacters, spaces, slashes, quotes, backticks, `$(...)`, newlines
     or a leading dash are refused: non-zero exit, nothing written to the
     output file, the raw name not in the output.
   - A defect gets the correct expectation and `t.Skip("defect: ...")`.
2. One fix commit per defect the test exposes, dropping its skip.
3. Changelog fragment `changelog.d/370-release-tag-tests.md`, then a
   simplify pass over the test code.

## Out of scope

- The rest of release.yml and the other release scripts.
- Tightening the accepted shape beyond the character check (for example
  requiring a semver after `v`).
