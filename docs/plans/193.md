# Plan: #193 intel-sgx backend and attestation

## Objective

Ship `backends/intelsgx`, its own module that requires a released root, as an
Intel SGX backend: probe the host, construct a `Backend`, hand out enclave
handles, and produce attestation evidence. Design: `docs/backends/intel-sgx.md`.

## Slices, in order

1. Module skeleton: `doc.go`, `go.mod`, typed errors (`errors.go`) with
   sentinels and `Is`/`Unwrap` struct types. Tests: `errors` cases in
   `backend_test.go`.
2. Probe: `probe_linux_amd64.go` (device and CPUID checks) and
   `probe_other.go` for every other platform. Tests:
   `probe_linux_amd64_test.go`, `probe_other_test.go`; Probe refuses an
   unconstructed Backend.
3. Backend and handles: `backend.go`, `handle.go`, `layout.go`. Tests:
   `backend_test.go`, `handle_test.go`, `layout_test.go`.
4. Attestation: `attest.go`, `attest_linux_amd64.go`, `attest_other.go`.
   Tests: `attest_test.go`, `attest_other_test.go`.
5. Wiring: `BACKEND_MODULES` in the Makefile runs the module under
   `make test-backends`; changelog fragment `changelog.d/intel-sgx.md`.
6. Merge main (keeps main's `backends/imxele` beside `backends/intelsgx`),
   pass the gates, mark PR #353 ready.
7. Review round 1: `quoteOver` rechecks the context after the report-data
   write and after the quote read. Tests: `attest_linux_amd64_test.go` drives
   `Attest` to a successful quote through stand-in pseudo-files (concurrent
   nonces, foreign and malformed quotes, both cancellation points).
   `conformance_sgx_test.go` (tag `sgx`) runs `backendtest.TestBackend` with
   `VerifyEvidence` and concurrent `Attest` on the real part.

## Open, for the owner

- Approval of the SPEC row change (future to planned) and decisions on the
  design's open questions, which the code takes at their recommended options.
- The SGX host and runner (Q10), and the DCAP verifier (PCK chain, quote
  signature, TCB) the hardware runner supplies to `VerifyEvidence`.

## Out of scope

- SGX device paths in CI: they need SGX hardware. The module's unit tests
  run, but like the other backend modules it is not held to the coverage
  floor.
- Remote verification of attestation evidence by a relying party.
- Registering the backend from the root module: `main` calls `Register`.
