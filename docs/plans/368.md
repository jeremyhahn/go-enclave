# Plan: providertest error contract (#368)

## Objective

Hold every exported error type and `Err...` sentinel of `providertest` to one
contract, checked by one table test, with a completeness check so a new error
type cannot land without a row.

## Slices, in order

1. Test commit: `providertest/errors_contract_test.go`.
   - `TestErrorContract`: one row per exported error type
     (`ConfigError`, `AbortedError`, `FindingsError`, `PropertyError`,
     `NotMeasuredError`), each with a zero and a populated value:
     - `Error()` does not panic, is non-empty and starts with
       `providertest: `;
     - `errors.Is` matches the row's sentinels and no other package
       sentinel;
     - `errors.As` reaches the concrete type through `%w` one and two
       levels deep and through `errors.Join`;
     - `Unwrap` (single or `[]error`) exposes the cause; a nil cause
       unwraps to nil.
   - `TestErrorContractIsComplete`: parses the package's non-test files
     with `go/parser`, collects exported `...Error` types and `Err...`
     sentinels, and fails on a type without both a zero and a populated
     row, or a sentinel missing from the table or matched by no row.
   - Rows exposing a real defect carry the correct expectation and
     `t.Skip("defect: ...")`.
2. One fix commit per defect the table exposes, in `providertest/errors.go`,
   dropping its skip.
3. Changelog fragment `changelog.d/368-providertest-errors.md`, then a
   simplify pass over the new test code.

## Out of scope

- The root package's error types (issue #345).
- Unexported error types (`stepError`, `nilProviderError`,
  `missingSeamError`).
- Any message change other than a fixed defect.
