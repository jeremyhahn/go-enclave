# Plan: consumer-check covers providertest (#343)

## Objective

`make consumer-check` builds `scripts/testdata/consumer/main.go` against a
published tag in a scratch module (GOWORK=off), and the buildgates test
`TestScriptsConsumerCheck_TheWorkingTreeServesAWorkingConsumer` builds it
against the working tree served as a module. The program imports only the
root package today. It should also import `providertest` and run
`providertest.TestProvider` against `enclave.NewSoftwareProvider()`, so the
provider-author SDK is built and run from an outside module.

## Slices

1. Consumer program: a `conformance` step in `run()` after the lifecycle and
   sealing checks, claiming both sealing modes, with the residue sweep
   skipped (host-dependent and slow; providertest's own tests measure it).
   Package comment names the new check.
   Test: `make check-scripts` passes; a temporary rename of an exported
   `providertest.Config` field fails the consumer test (not committed).
2. Changelog fragment `changelog.d/343-consumer-sdk.md` (`### Added`).

## Out of scope

- Any change to `providertest` itself or to `scripts/consumer-check.sh`.
- The scratch module needs no extra `go get`: `providertest` is a package of
  the root module and adds no dependency the root does not already have.
