# Plan: intel-tdx backend (#199)

Design: [docs/backends/intel-tdx.md](../backends/intel-tdx.md). Where its open
questions leave a choice, the code takes the recommended option and names it
in a comment.

## Objective

A nested Go module `backends/inteltdx`, laid out like `backends/armtrustzone`:
its own go.mod requiring go-enclave and golang.org/x/sys, never the reverse;
nothing registers at import. The device code is `linux && amd64`; every other
target builds a stub whose constructor and probe return the typed unavailable
error. The backend is proven on the real part only (owner ruling): no
simulator, emulator, mock device or fake device tree.

## Slices

1. **Module, typed errors, probe, refusal path** (this slice).
   - go.mod/go.sum, doc.go, errors.go (`*GuestDeviceError`, `ErrDebugTD`,
     `*TSMReportError`, `ErrTSMReportConflict`, `*MeasurementRegisterError`).
   - Probe (Q3, recommended: TDREPORT, DEBUG bit, one quote): ctx, then
     `/dev/tdx_guest` `TDX_CMD_GET_REPORT0`, refuse ATTRIBUTES.DEBUG, then one
     configfs-tsm quote over a probe nonce, discarded.
   - `New()` runs the probe; `Name` `intel-tdx`, `Rank` 10 (Q2),
     `ConfinesProcess` true. Not `Sweeper` (Q7).
   - Tests: error texts, `errors.Is`/`As` and unwrapping; the TDREPORT
     DEBUG-bit parser, the request layout and the ioctl number on fixed
     byte buffers; the provider and generation checks; on a host without the device, `Probe` and `New` return
     `*GuestDeviceError` (`open`, `ENOENT`); the stub's typed error.
   - Makefile `BACKEND_MODULES` gains the module (tidy, lint, test-backends,
     cross-build, govulncheck).
2. **Import and handles** (Q6): `Import` into `enclave.NewMemory`, handles
   with `ByteAccess` and `Freezer`; unit tests that need no device.
3. **Attest** (Q4, Q5): per-call report directory, zero-padded 64-byte
   REPORTDATA (and its layout test), `provider`/`generation` checks, `Evidence{Format: "tdx_guest"}`,
   `ErrInvalidNonce` widened to `Attest` in the root.
4. **Native interface**: `Report`, `Measurements`, `ExtendRTMR` (Q8),
   `*MeasurementRegisterError` below Linux 6.16.
5. **In-hardware conformance**: `make integration-test-intel-tdx`
   (`-tags=integration`) inside a TD on the owner's TDX host: backendtest,
   Detect, concurrent Attest, RTMR extend, QGS outage, DEBUG TD.

## Out of scope

Any test of the device paths off the real part; a quote parser or verifier
(the backend never appraises a quote); a `Sweeper`; RTMR extension by the
backend itself; platforms other than Linux on x86-64 at run time.

## Departures

Q1 recommends a separate repository (`go-enclave-tdx`); the brief places the
module nested at `backends/inteltdx`, as armtrustzone and tpm are, with the
same one-way dependency.
