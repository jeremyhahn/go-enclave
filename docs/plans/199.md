# Plan: intel-tdx (#199)

## Objective

The intel-tdx proposal ([docs/backends/intel-tdx.md](../backends/intel-tdx.md))
lists nine open questions with options but no proposed answers. This epic
first puts one proposed answer under each question, ready for the owner's
sign-off, so the row can move once an Intel TDX host exists. The row stays
`future`.

## Slices

1. **Proposed answers to the open questions** (this slice). Under each of
   Q1 to Q9 add one line "Proposed answer (for owner sign-off): ..." with a
   one-sentence reason: the section's recommended option, kept consistent
   with the amd-sev proposal and the ruled arm-trustzone design. Q2 (rank)
   and Q9 (the verifier the tests use) are left explicitly for the owner.
   Every option stays as written. A changelog fragment records it.
   Tests: `make check-docs-links`, `make check-changelog-assembly`.
2. **After sign-off** (later, once a host exists): each answer replaces its
   options in the proposal, and the SPEC row moves from `future` to
   `planned`.

## Out of scope

- Go code, the backend module, its tests.
- SPEC and ROADMAP changes: no host for this row exists yet.
- The amd-sev and arm-trustzone documents.
