# Plan: unit tests for the integration suites' devcontainer guard (#344)

## Objective

`test/integration/internal/devcontainer` decides whether every integration
suite may run, and has no tests. Split the guard's inputs from its checks so
every refusal can be table-tested outside the devcontainer, with each message
asserted, and run those tests from a target CI already runs.

## Slices, in order

1. Test commit, on the current code: the env parsers (`envUint64`,
   `EnvInt64`: missing, zero, negative, non-numeric, valid), `checkFIPSMode`
   for each bad mode string, and `Problems` refusing when
   `GO_ENCLAVE_IT_DEVCONTAINER` is not 1.
2. Refactor commit: `Problems()` keeps its signature and messages and
   delegates to the unexported pure `problemsFrom(in inputs) []string`.
   `inputs` carries the env lookup, the `/proc/self/status` text, the euid,
   the RLIMIT_MEMLOCK soft/hard pair (or its error) and the FIPS
   enabled/enforced pair. The status parsers take the text. New table cases:
   non-zero CapEff/CapPrm/CapBnd/CapAmb, CAP_IPC_LOCK named, NoNewPrivs 0, a
   missing status line, a malformed status value, memlock soft or hard
   mismatch, getrlimit error, root euid, FIPS only-but-disabled and
   off-but-enabled, and the clean case returning nil.
3. Makefile commit: `make lint-integration` runs this package's tests (one
   line). Changelog fragment commit: `changelog.d/344-it-guard-tests.md`.

## Out of scope

- Any change to what the guard checks or to its messages.
- `Refuse` itself (it exits the process); it stays a thin wrapper.
- The suites that call the guard, and `compose.yaml`.
