# Plan: relative Markdown link gate (#339)

## Objective

Every relative link in the repository's tracked Markdown resolves, and a
build gate in `build/ci/buildgates` holds it. Today no gate checks them, and
six links in `docs/backends/` point at a `linux-secretmem.md` sibling that no
longer exists (the feature lives in `docs/linux-secretmem/`).

## Slices, in order

1. Gate (test commit). `build/ci/buildgates/markdown_links_test.go` adds
   `TestMarkdownRelativeLinksResolve`: it walks tracked `*.md` outside
   `docs/reference/` and `changelog.d/`, skips fenced blocks and inline code
   spans, and checks each relative link target:
   - a repository path (anchor and query stripped) must exist;
   - a target that leaves the repository must be `issues/N`, `pull/N` or
     `milestone/N`, reached by exactly the `../` depth that climbs from
     `blob/main/<dir>/` to the repository root (`../../` for root files,
     one more per directory level).
   Unit tests pin the link extractor (fence, code span, reference
   definition) and the classifier (repo path, anchor-only, URL, right and
   wrong `../` depth). The gate fails on main, naming file:line for each of
   the six broken links.
2. Fix commit. The six link targets in `docs/backends/amd-sev.md`,
   `intel-tdx.md`, `imx-edgelock-enclave.md` and `nvidia-blackwell.md` point
   at `../linux-secretmem/architecture.md`; the `#q3-rank` anchor becomes the
   heading that holds the rank decision (`#d3-rank-1`). The gate passes.
3. Changelog fragment `changelog.d/339-md-link-gate.md`.

## Out of scope

- Anchor checking (a heading named by `#fragment` is not verified).
- Absolute URLs and links to other repositories' files.
- Prose changes in any document.
