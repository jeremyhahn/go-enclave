# Plan: SPEC row public-release

Row `public-release` of [docs/SPEC.md](../SPEC.md), branch
`row/456-public-release`, one PR.

## Objective

The first public release is a plain `vX.Y.Z` tag cut from `main` with
`make release`, after a release candidate has passed its tag workflow and
staging. The published tree names no private host
(`make check-releasability`), and breaking changes from that release on ship
with their migration in [Upgrading](../README.md#upgrading).

## Slices, in order

1. Fold the earlier per-item PRs into the row branch, each with a merge
   commit:
   - runnable examples for the memory enclave, allocator, detection and
     sweep, with their changelog fragment (`example_test.go`; the examples
     are the tests: `go test` checks each `// Output:`);
   - Upgrading notes for v0.10, v0.11 and the next release
     (`docs/README.md`);
   - `golang.org/x/sys` v0.50.0 in every module (`make deps-check` holds
     that each module is at the latest release).
   Tests: `make test-enclave` (examples), `make test-backends`,
   `make lint-gates` (changelog fragments and feature map).
2. Cut the release: a release candidate tag passes its tag workflow and
   staging, then `make release` cuts the plain `vX.Y.Z` tag from `main`.
   This is done by the coordinator, not a lane: a lane pushes no tags.
3. Mark the row shipped in `docs/SPEC.md` and `ROADMAP.md` once the tag
   exists.

## Out of scope

- New features or API changes; the future backends (SPEC release
  criterion 1).
- Release tooling changes: `make release` and `make check-releasability`
  already exist and have their own tests.
