# Plan: confiner-sev-snp

## Objective

SPEC row `confiner-sev-snp`, designed in
[docs/backends/amd-sev-snp.md](../backends/amd-sev-snp.md): the Confiner
backend in `backends/amdsev`, which claims the process only inside an AMD
SEV-SNP guest whose policy has DEBUG clear, and refuses with a typed error
everywhere else. Attestation and hardware key protectors belong to go-xkms
(SPEC scope), not to this row. Proven on the real part only.

## Slices

1. **Design (done, docs only).** Host record, proposed answers, SPEC row,
   changelog fragment.
2. **amd-sev module (done).** `backends/amdsev`: report parser,
   configfs-tsm client and probe, `New`, `Attest`, `Import`, `Sweep`, typed
   errors, off-platform stub. Tests: `make test-backends`.
3. **amd-sev guest kit (done).** `scripts/amd-sev-snp/amdsev-guest.sh`,
   `scripts/amd-sev-snp/amdsev-host-scan.sh` and its scanner (now the module's,
   item 12). Tests: the buildgates dry-run and refusal tests, the
   scanner's tests, lint-scripts.
4. **SNP derived key (done; superseded by 13).** `SNP_GET_DERIVED_KEY` through
   `/dev/sev-guest`, received in locked memory, wiped and released on every
   path. Tests: struct codecs, refusal off an SNP guest, wipe and release.
5. **intel-tdx module (done, folded; superseded by 13).** `backends/inteltdx`:
   probe, `Attest` over configfs-tsm, `Import`, the native `Report`,
   `Measurements` and `ExtendRTMR`. Tests: `make test-backends`.
6. **Standalone Attester (done; superseded by 13).** `backends/confidentialvm`:
   `NewAttester` reads the configfs-tsm provider (`sev_guest` or
   `tdx_guest`); `Attest` returns `sev-snp-report` or `tdx-quote` evidence
   from an entry of its own, checking provider and generation; typed
   `*TSMReportError`; off-platform stub; the root `Attester` doc comment
   gains its third placement. Tests: nonce layout, provider mapping,
   generation, each refused step against a real directory, the stub.
7. **SNP KeyProtector (done; superseded by 13).** `NewKeyProtector` for `ModePerOperation`
   records VMPL, guest SVN and committed TCB from one SNP report, derives
   per call in locked memory; blob is version, `MSG_KEY_REQ`, nonce,
   AES-256-GCM. Tests: codec, every altered byte, binding and TCB refusals,
   the refused ioctl on a regular file. `providertest` runs in item 10.
8. **Drop the backend drafts (superseded by 13).** Remove `backends/amdsev` and
   `backends/inteltdx` (their `Import`, `Sweep`, native and backend
   surface), keep the guest kit pointing at the new module, and fold their
   changelog entries into the new module's.
9. **Ship the row.** Mark `confiner-sev-snp` shipped in docs/SPEC.md and
   ROADMAP.md once the SNP hardware acceptance has run.
10. **Hardware runs (blocked on the hosts).** SNP host and TDX host: the
   design's test plan in a real guest.
11. **Review round 1 on the SEV-SNP kit.** Each fix follows a failing test:
   `hostscan.Scan` returns a typed incomplete-scan error when an eligible
   mapping cannot be read (test: a partially readable scan); the
   integration conformance config declares Confine and Import for the
   backend and Bytes and Freeze for its handle (test: backendtest accepts
   the config); `run.sh` builds `amdsev-hostscan` before the sudo step and
   passes it in `AMDSEV_HOSTSCAN` (test: the script's order).
12. **Review round 1, finding 2: the suite in its module.** The suite moves
   into `backends/amdsev/integration` behind the `amdsev` build tag, as
   `optee` and `swtpm` gate their hardware suites; no replace, no go.work.
   `make integration-test-amd-sev` boots a guest per mode in
   `AMDSEV_GUESTS` (default `sev sev-es`, the modes the hardware host
   provides; the SEV-SNP tests run where `snp` is listed and SNP is
   available) beside the plain KVM control. The workflow is
   `.github/workflows/amd-sev.yml` on the `amd-sev` runner label, started
   only while the `AMD_SEV_RUNNER` variable is `online`. Tests: the kit's
   tests and the suite's in-guest selection; the hardware run itself on
   the host. The second copy of the scanner, `scripts/amd-sev-snp/amdsev-hostscan`,
   goes: `amdsev-host-scan.sh` builds the module's
   `cmd/amdsev-hostscan`, as `host-scan.sh` does (test: the kit tests run
   both scripts). backends/confidentialvm requires the root and x/sys
   versions the other backend modules use, so it builds offline in CI.
13. **Review round 2: the row is the Confiner only.** The row is
   `confiner-sev-snp`; attestation and key protectors are go-xkms's (SPEC
   scope), so `backends/confidentialvm` (items 4, 6 and 7) goes, with its
   make, doc and changelog references, and the root `Attester` doc comment
   loses its third placement. `amd-sev.yml` is the SEV and SEV-ES hardware
   job: the hardware host has no SEV-SNP, so its SEV-SNP step reports "SNP
   not available on this runner" and fails nothing, while every SEV and
   SEV-ES check still runs. SNP hardware acceptance (items 3 and 4 of the
   design's test plan in an SNP guest) stays open, pending an SEV-SNP host;
   the row stays in progress.
14. **Guest cleanup.** the hardware test starts the launcher in its own process
   group (`guest.sh` runs `timeout --foreground`, so QEMU stays in it) and
   registers a cleanup right after `Start` that ends the whole group, SIGTERM
   then SIGKILL, on every path. Test: `TestTerminateGroup_*`, which runs
   without SEV hardware.
15. **Review round 2, finding 1: an SNP-only job.** The SEV and SEV-ES job
   drops its SNP step (this replaces item 13's skip-on-no-SNP step). A
   separate `amd-sev-snp` job, on the `amd-sev-snp` runner label and
   started only while `AMD_SEV_SNP_RUNNER` is `online`, runs the target
   with `AMDSEV_GUESTS=snp` and its plain KVM control, and fails with an
   error annotation unless `kvm_amd` reports `sev_snp`. Test:
   `TestAMDSEVWorkflow_*` in `build/ci/buildgates`, which also runs the
   check step against Y, 1, N, 0 and an absent parameter. The passing SNP
   run stays open until an SEV-SNP host is registered.
16. **One branch for the confiner row.** The Intel SGX branch
   (`backends/intelsgx`, its design `docs/backends/intel-sgx.md`, its plan
   `docs/plans/193.md` and its changelog lines) merges into this branch
   with its history; `BACKEND_MODULES` lists both nested modules. No
   behaviour change beyond what that branch carries.

## Out of scope

- A simulator, emulator or mock device.
- Registering anything at import: `main` calls `Register`.
- Any root-module change beyond the `Attester` doc comment.
