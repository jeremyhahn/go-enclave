# Plan: amd-sev (#194)

## Objective

The `amd-sev` backend for programs in an AMD SEV-SNP guest on Linux amd64,
as a module of its own (`backends/amdsev`), designed in
[docs/backends/amd-sev.md](../backends/amd-sev.md) and proven on the real
part only.

## Slices

1. **Design (done, docs only).** The host record in the proposal's test
   plan, a proposed answer to each open question (Q1 to Q9), the SPEC row
   `planned`, the ROADMAP bullet under Next, a changelog fragment.
   Tests: the doc and changelog gates.
2. **Backend module (done).** `backends/amdsev`: the ATTESTATION_REPORT
   parser, the configfs-tsm report client and probe, `New`, `Attest`,
   `Import` and `Sweep`, typed errors and the off-platform stub; the module
   is linted, tested, tidied and cross-built with the other backend
   modules. Tests: the module's unit tests (`make test-backends`).
3. **Guest kit (done).** `scripts/amdsev-guest.sh` (SNP, SEV-ES or plain
   guest, `--dry-run`) and `scripts/amdsev-host-scan.sh` with the
   `scripts/amdsev-hostscan` helper for test plan step 5. Tests: the
   buildgates dry-run and refusal tests, the helper's unit tests, the
   lint-scripts operands.
4. **Derived key (done).** `SNP_GET_DERIVED_KEY` through `/dev/sev-guest`;
   the backend is a `RootUnsealer` that receives the key in locked memory,
   wiped and released on every path. Tests: the struct codecs, the refusal
   outside an SNP guest, the wipe and release of the response.
5. **Host ready (blocked on the host).** Once SNP is enabled on the host and
   `/dev/sev` is granted: complete the host record and run test plan steps
   2 to 6 in a real SNP guest.
6. **SVSM** (if Q7 is ruled in): test plan step 7.

## Out of scope

- A simulator, emulator or mock device.
- Registering the backend at import: `main` calls `Register`.
- Any change to the root module.
