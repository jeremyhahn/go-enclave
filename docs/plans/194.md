# Plan: amd-sev guest kit (#194, slice 2)

## Objective

The amd-sev test plan on the real hardware (docs/backends/amd-sev.md, "Test
plan on the real hardware") needs a kit that launches guests on the SEV host
and runs the backend module's tests inside them, and a host-side scan of the
QEMU process for a needle the guest holds. SNP is not on yet, so this slice
builds the kit and proves it by dry run and static checks. QEMU drives KVM on
the real CPU: no simulator, emulator or mock device of anything the backend
touches.

## Slices, in order

1. `build/ci/buildgates/amdsev_guest_test.go`: each mode's dry run of
   `scripts/amdsev-guest.sh` prints the expected QEMU objects (snp:
   `sev-snp-guest`, debug off, `kernel-hashes=on`; sev-es: `sev-guest` with the
   SEV-ES policy bit; plain: no SEV object), no network device in any mode, no
   download in either script, and a real run refuses without `/dev/kvm` or
   `/dev/sev`. Fails first: no script.
2. `scripts/amdsev-guest.sh` (modes `snp`, `sev-es`, `plain`, `--dry-run`)
   until slice 1 passes. POSIX sh with `set -eu`, sourcing `scripts/lib.sh`,
   like every script `make lint-scripts` checks with `--shell=sh` (the brief
   asked for bash; the project's scripts are POSIX sh, and lint enforces it).
3. Host scan: `scripts/amdsev-hostscan` (a small linux-only Go helper in the
   root module, since `backends/amdsev` does not exist yet) and
   `scripts/amdsev-host-scan.sh` calling it. Exit 0 not found, 1 found, 2
   error. Its test spawns a child holding a needle and scans the child's pid:
   the held needle is found, a fresh one the child never held is not.
4. One "Kit" paragraph in amd-sev.md's test plan; changelog fragment.

## Out of scope

- Building OVMF, the kernel or the initrd: the kit takes pinned paths and
  downloads nothing.
- The first real SNP run (needs SNP enabled on the host), the self-hosted
  runner workflow, and the attestation verifier (test plan step 3).
- `backends/amdsev` itself.
