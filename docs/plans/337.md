# Plan: a fuzz target for the TrustZone KeyProtector.Unprotect (#337)

## Objective

`FuzzKeyProtectorUnprotect` drives arbitrary blobs, key lengths and context
states through `KeyProtector.Unprotect`, and through the client,
shared-memory and driver path under it, on the in-process fake TEE, with
both drivers (registered memory and driver memory). No TEE device and no
OP-TEE image are needed.

## Slices

1. Test: `backends/armtrustzone/protector_fuzz_linux_test.go`.
   - One fake TEE and one Backend per driver for the whole run, built
     outside `f.Fuzz`; the two fakes share one sealing key, so one
     `Protect` blob for a 32-byte key opens on both.
   - Seeds: that blob, its truncations, single-bit flips at 0, 12, the
     middle and the last byte, an empty blob, a `sealMaxBlob+1` blob; key
     lengths 0, 31, 32, 33; context live, canceled, expired.
   - Properties, per input and driver: no panic; a live context opens only
     the untouched blob into a 32-byte key and yields that key; any other
     input fails with `enclave.ErrSealedAuthentication` and a zeroed key;
     an ended context returns `ctx.Err()` and runs no UNSEAL; the blob is
     unchanged; no shared memory stays live; the fake records no fault and
     no extra session or device fd.
   - `newFakeTEE` takes `testing.TB` so a `*testing.F` can build it.
2. Run `go test -race ./...` and a 60 s fuzz run. A crasher is committed
   under `testdata/fuzz` as a failing test, then fixed in its own commit.
3. Changelog fragment `changelog.d/337-tz-unprotect-fuzz.md`.

## Out of scope

- Fuzzing `Protect`, or the real OP-TEE fixture.
- Any non-test change unless the fuzz target finds a contract break.
