# Plan: ci.yml template v1.53 and v1.54

## Objective

Adopt the ci.yml template v1.53, then v1.54's runner selection, and keep CI Gate green on it: every workflow
of the repository passes the runner-label check, and every helper script
ci.yml calls ships in the tree.

## Slices

1. ci.yml v1.53 and the buildgates pins of its version and main concurrency
   group (done).
2. Runner labels on the repository's own workflows.
   - Test: `TestRunnerLabelsPassOnOwnWorkflows` runs ci.yml's
     `Runner labels` step over `.github/workflows/` and expects no finding.
   - Fix: the `publish` job of `ghcr-optee-fixture.yml` names its category,
     `# self-hosted: hardware: <reason>`. The check itself is not changed.
3. The helper scripts ci.yml calls.
   - Test: a buildgates test that every `scripts/*.sh` a ci.yml step runs
     exists and is executable.
   - Fix: `scripts/ci-mask-lan.sh` and `scripts/ci-image-history.sh`, copied
     byte for byte from the template, mode 755. Both are bash, so they join
     the Makefile's CI_BASH_SCRIPTS and the template scripts the lib.sh rule
     in features_test.go exempts, like ci-image-cache.sh.

4. The image build's module proxy as a BuildKit secret: ci.yml's
   image-history check refuses an image whose history holds a private
   proxy address, and Docker records a build argument a RUN reads.
   - Test: `TestImageBuildProxyIsABuildKitSecret`: the Dockerfile declares no
     `ARG GO_BUILD_PROXY` and every RUN that sets GOPROXY mounts the
     `goproxy` secret; the Makefile's docker-build-toolchain recipe and
     `scripts/devcontainer.sh` pass `--secret id=goproxy,env=GO_BUILD_PROXY`,
     never `--build-arg`.
   - Fix: the Dockerfile reads the secret, defaulting to the public proxy
     (no `direct`) when none is passed; both build paths pass the secret
     only when GO_BUILD_PROXY is set; the older proxy gate follows.
5. The template's Python suites in lint-gates.
   - Test: `lint-gates` depends on a target that runs
     `testdata/ci-mask-lan-tests.py` and `testdata/job-output-handoff-tests.py`.
   - Fix: `check-ci-python-suites`, each suite under `python3 -I`, in
     lint-gates' prerequisites.
6. The runner-select suite in lint-gates; the proxy text names the secret.
   - Test: lint-gates runs the template's runner-select suite beside the
     other Python suites; no build passes the proxy as a build argument.
   - Fix: `check-ci-python-suites` runs the runner-select suite; the
     comments and docs that described the proxy build argument name the
     BuildKit secret.
   - Docs: `docs/build-and-release.md` describes CI concurrency, tiers and
     runner selection as ci.yml v1.53 runs them; the job table names the
     runner Preflight selects, not `ubuntu-latest`.
   - Gate: the env fixture's private-range `GOPROXY` entry in
     `testdata/ci-mask-lan-tests.py` carries the releasability gate's
     `lab-string-ok:` waiver, as its neighbours do; the value is unchanged.

7. ci.yml v1.54: the balanced runner pool; a fork never self-hosted.
   - Test: buildgates pins the step, its env and outputs, every runs-on,
     and runs the step: a fork gets the hosted default with no API call.
   - Fix: the v1.54 hunks of ci.yml; the v1.54 runner-select suite.
## Out of scope

- Any change to the checks in ci.yml.
- The integration image's build: it takes no proxy and uses the public
  default.
