### Added

- **confidential-vm**: A new module, backends/amdsev, is the amd-sev backend for programs in an AMD SEV-SNP guest on Linux amd64: it attests with the firmware's 1184-byte report through configfs-tsm, keeps imported material in memory enclaves in the guest's encrypted memory, and returns ErrSNPGuestUnavailable naming the failing step on a host that cannot attest or on other platforms. Nothing registers it at import, and the root module is unchanged.
- **confidential-vm**: The amd-sev backend is a RootUnsealer whose UnsealRoot receives, in locked memory wiped and released on every path, a 32-byte key the firmware derives through /dev/sev-guest from the chip's VCEK, bound to the guest's policy and launch measurement, so a sealed root opens only for the same guest image on the same chip. A refused request returns ErrSNPGuestUnavailable or ErrSNPReport with a FirmwareError carrying the firmware's and the hypervisor's error words, and writes no key material.
- **confidential-vm**: A test kit for the amd-sev backend on real hardware: scripts/amdsev-guest.sh launches an SNP, SEV-ES or plain KVM guest from a pinned local OVMF build and a direct-boot kernel with no network device and exits with the guest test binary's status (--dry-run prints the QEMU command), and scripts/amdsev-host-scan.sh scans a QEMU process's readable memory on the host for a needle the guest holds, exiting 2 when any readable mapping cannot be read. Neither downloads anything.
